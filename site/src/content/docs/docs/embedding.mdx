The `worgl` crate is the issuer itself: ledger, note format, transfer
protocol, policy, issuer state machine and crash-safe storage. The server is
built on it. Embed it when your program should be the mint, rather than talk
to one over HTTP.

```sh
cargo add --git https://github.com/zhangheqi/worgl worgl
```

## Keeping it on disk

`Issuer` lives in memory. For durability, wrap it in `PersistentIssuer`,
which logs every event before applying it. Each change is an `Event` that
the issuer plans without side effects, the store writes and flushes to a
log, and only then the issuer applies. Applying is deterministic and
checked, so a snapshot plus its log rebuilds the exact same state, and a note
is never handed out unless the event that created it is on disk.

A store is a directory holding `snapshot.bin`, `log.bin`, `keys.bin` (the
generation keys' secrets, readable by its owner only) and `lock`, which
stops two processes from writing the same store. See [Backups](../backups/).

- `PersistentIssuer::create(dir, issuer)` makes a store for a new issuer;
  `PersistentIssuer::open(dir, key, policy)` opens one.
- `batch()` starts a group commit: each change takes effect in memory as it
  is made, and all of them reach the disk in one log entry and one flush.
  Nothing a batch returns may be handed out before it commits. The server
  puts every request waiting at the moment of a flush into one batch.
- `compact()` writes a fresh snapshot and purges the log up to it. Call it
  after rotations or whenever `log_events()` grows large.

If a batch's flush fails, the issuer is ahead of its log: `issuer()` still
shows the batch's changes, which never reached the disk, so do not answer
reads from it, and every further change is refused, until `recover()`
rebuilds it from the snapshot and log on disk or the store is reopened;
either restores exactly what reached the disk. A single change whose flush
fails is not applied at all. If the log could not even be cut back after a
failed write, the store is stopped instead, and only reopening it reads the
log again. `state()` tells which it is: `InStep`, `Ahead` or `Stopped`.
Opening compacts the log, and if that fails, as on a full disk, opens from
the snapshot and log as they are; `take_compaction_error()` then tells why.

## Checking signatures outside a lock

To keep signature checks out of a lock, verify with `issuer.verifier()`
first and pass the `VerifiedTransfer` in. A verifier is bound to the
issuer's keys and policy as they are when you get it; a rotation adds a key,
so get a new one after each.

## Minting

`Issuer::mint` mints directly, for code that embeds the issuer. A server
should take signed mint requests instead: `Issuer::authorized_mint` accepts
a `MintRequest` signed by a key the policy lists in `mint_authorities`, and
logs the signature with the note. See
[Mint authorities and keys](../keys/).
